# Installation

## Prerequisites

Use a Linux host with Docker Engine and Docker Compose plugin, DNS for the public
HTTP name, an HTTPS reverse proxy, and firewall access to TCP 443 and TCP 2222
(or your chosen SSH port). TCP 80 is normally needed only for ACME HTTP-01.
Grading needs Docker access, but the application does not get it: the socket is
held by a separate runner service that only ever grades a submission. Set
`GRADING_RUNNER_SECRET` in `.env` — both halves refuse to start without it — and
read the [security guidance](security.md) for what that boundary does and does
not cover.

## Compose

```sh
git clone git@github.com:git-grader/gitgrader.git
cd gitgrader
./scripts/install.sh
scripts/verify-install.sh
```

`install.sh` writes `.env` from the example, fills in the group that owns the
Docker socket, builds the image if it is missing, starts everything and waits
until it answers. Running it again skips whatever is already done. Add `--demo`
to load the sample course as well.

Then edit `.env` and restart: both database passwords, `APP_PUBLIC_URL`, the
public SSH name and port, and the cookie policy. `scripts/verify-install.sh`
checks readiness, `/api/v1/meta` and the SSH port.

There is no Dockerfile. The image is produced by buildpacks, which is what
`install.sh` runs and what `./mvnw spring-boot:build-image -pl backend` does on
its own. The published image is only available once a release has been tagged.

The application container carries no health check. The image it is built on has
no shell for one to run in, and a check that can never pass hides a crash loop
behind what looks like a slow start. Probe it from outside instead:
`curl -sf http://localhost:8080/actuator/health/readiness`.

Run `scripts/generate-host-key.sh` only when a persistent host key has not yet
been generated by the embedded server; never replace a live host key casually,
or users will receive a host-key warning.

## Reverse proxy and TLS

Terminate HTTPS before the application and set `SERVER_FORWARD_HEADERS_STRATEGY=framework`
only when the proxy is trusted. Keep SSH as direct TCP forwarding; HTTP reverse
proxies do not carry Git-over-SSH.

**nginx**:

```nginx
server { listen 443 ssl http2; server_name grader.example.org;
  ssl_certificate /etc/letsencrypt/live/grader.example.org/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/grader.example.org/privkey.pem;
  location / { proxy_pass http://127.0.0.1:8080; proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; }
}
```

**Traefik**: route `Host(``grader.example.org``)` to port 8080 with a TLS
resolver; set the equivalent forwarded headers only from Traefik’s trusted
network. **Caddy**:

```caddy
grader.example.org { reverse_proxy 127.0.0.1:8080 }
```

Forward `2222:2222` at the firewall/NAT and set `GIT_SSH_HOST=grader.example.org`
and `GIT_SSH_PORT=2222`. Do not expose PostgreSQL.

Behind any of these, set `SERVER_FORWARD_HEADERS_STRATEGY=framework` so the
application resolves the real client instead of the proxy. Rate limits count
whatever the container reports as the remote address, so left at the `none`
default every request appears to come from the proxy and one caller's attempts
are counted against everybody. Set it only where the proxy overwrites the
forwarded header rather than passing a client-supplied one through.

## First-run checklist

- Change generated database passwords and store `.env` as a secret.
- Set the HTTPS `APP_PUBLIC_URL`, public SSH name/port, support email, and proxy
  forwarding strategy.
- Confirm persistent volumes are backed up and perform a restore drill.
- Restrict `config/`, Docker socket/proxy access, Actuator, logs, and backups.
- Create/integrate administrator identity, runtime definitions, templates, and
  hidden test suites before publishing an assignment.

## LDAP

Set `SECURITY_LDAP_ENABLED=true`, `SECURITY_LDAP_URL` to an `ldaps://` endpoint,
base DN, protected manager credentials, user and group search bases and filters,
plus instructor/admin group names. A plain `ldap://` URL is refused at startup
outside the development and test profiles: the instructor password and the
manager bind credentials cross that connection. Test with a non-privileged
directory account first, then disable local accounts. Never enable LDAP debug
logging in production because it may expose bind credentials or directory data.

## Public URL

`APP_PUBLIC_URL` is what every result link is built from, and that link is the whole
credential for a student's marks. Under the production profile it has to be an `https://`
URL; loopback is the exception, because that is the demo. An instance configured with a
plain `http://` hostname refuses to start rather than mailing out bearer tokens in the
clear.

## Profiles

The application reads `SPRING_PROFILES_ACTIVE`. The Compose file sets
`production` for you; a jar deployment has to set it itself:

```sh
SPRING_PROFILES_ACTIVE=production java -jar gitgrader.jar
```

`production` disables local accounts, requires the database credentials to be
supplied, restricts actuator exposure and hides the interactive API console.
`dev` is the opposite and is what the demo runs. Nothing in `docs/configuration.md`
is reloaded while the application runs; changing any of it means a restart.
